# 設計ノート — なぜこの形なのか

> フル版（図・表つき）: <https://claude.ai/code/artifact/d276fd7d-69d4-48cc-b6f9-e766965b1465>

## コンセプト

**「記録するSNS」ではなく、明日の釣行を10秒で決めるための掲示板。**

アングラーズは釣った *後* の記録に最適化されている。イマツレは釣りに行く *前* の意思決定
——どこへ、何時に、何を持って——を最短にする。

## 競合（アングラーズ）の構造と、そこから生まれる見にくさ

| アングラーズの構造 | 生まれる問題 | イマツレの答え |
|---|---|---|
| 写真が主役の縦フィード | 1画面にほぼ1件。比較が成立しない | テキスト優先の高密度リスト |
| 1投稿＝1匹の粒度 | 同じ日の釣果が複数並び、水増しして見える | **1行＝1釣行**。魚は釣行にぶら下げる |
| 時系列が絶対軸 | 「先週の大潮の朝は？」で切れない | 潮・時間帯・釣り方のフィルタを常時表示 |
| 位置は市町村単位にぼかす | 「結局どこ？」が分からず実用性が落ちる | 公開範囲を投稿者が4段階から選ぶ |
| SNS的ないいね／コメント | 相談・募集・現地情報が流れて消える | 釣り場ごとの常設ボードとスレッドを分ける |
| 詳細検索が有料 | 価値を体験する前に壁に当たる | 閲覧と検索は全面無料 |
| 釣果情報の拡散 | 人が殺到し釣り禁止になる批判が実在 | **ルールを釣況より上に常設** |

## 差別化の4本柱

1. **1行＝1釣行（トリップ単位）** — `Trip` と `Catch` を分ける。これをしないと、一覧の水増し・統計の破綻・ボウズを記録できない、の3つが同時に起きる
2. **鮮度を色で持つ** — 今日／昨日／N日前を色の濃さで。屋外で視線を止めずに新旧が分かる
3. **テキストファースト** — 一覧に画像を出さない。写真は開いてから遅延読み込み
4. **ルールを釣況より上に** — 立入禁止・駐車・地元ルール・安全を第一級の情報として常設

## 「見やすさ」の設計原則

実装時のチェックリスト。

| # | 原則 | 守る数値 |
|---|---|---|
| 1 | 本文の最小サイズ | 15px以上（日本語は英字より小さく見える） |
| 2 | コントラスト比 | 本文 4.5:1 以上、補助文字も 3:1 以上（WCAG AA） |
| 3 | タップ領域 | 44×44px 以上 |
| 4 | 1画面の情報量 | スマホ縦1画面に釣行5件以上 |
| 5 | 色の役割を固定 | ティール＝釣況／マゼンタ＝規制・注意／オレンジ＝ピーク |
| 6 | 数字は等幅で揃える | `font-variant-numeric: tabular-nums` |
| 7 | フィルタは常に見える | スクロールしても消えない（sticky） |
| 8 | 初期表示の重さ | 一覧の初期表示 200KB 未満、1.5秒以内に文字が出る |
| 9 | ダークモード | 反転ではなく専用の色を組む |
| 10 | PCは3ペイン | 釣り場 → 釣況 → 詳細。遷移なしで比較できる |

## MVPの範囲

**やる**: 釣り場ボード／釣況リスト／釣行投稿／フィルタ／スレッド／ルール掲示／登録・ログイン／写真／通報

**後回し**: 潮汐の自動取得・地図・フォロー／いいね・ネイティブアプリ

**やらない**: ランキング・大会（競争を煽ると乱獲と場荒れを助長する）

## URL設計

| URL | 画面 |
|---|---|
| `/` | ホーム（釣り場を選ぶ） |
| `/spots/:slug` | **釣り場ボード（釣況）** ← サービスの中心 |
| `/spots/:slug/threads` | スレッド一覧 |
| `/spots/:slug/rules` | ルール |
| `/threads/:id` | スレッド詳細 |
| `/trips/:id` | 釣行詳細 |
| `/trips/new` | 釣行投稿 |
| `/login` | ログイン・登録 |

## 釣り場を潰さないための設計

1. 公開範囲の**既定値をエリア（ぼかし）にする** — 既定値の設計は倫理の設計
2. ルールタブを釣況より上に表示する
3. ランキング・大会を作らない
4. 「現地で確認した」ボタンで、古い情報が自然に沈むようにする
5. `expiresAt` で工事・期間限定情報を自動で落とす
6. 写真のExif（GPS）を保存時に必ず削除する

## KPI

| KPI | 初期目標 |
|---|---|
| 釣況到達時間（開いてから直近3日の釣果に目が止まるまで） | 3秒以内 |
| 「今週何が釣れたか」を答えるまでのスクロール | 2回以内 |
| 初期表示速度（LCP） | 1.5秒未満 |
| 投稿完了率 | 70%以上 |
| 釣り場あたり週次釣行数 | 主要5釣り場で10件／週 |

## ロードマップ

| Phase | 内容 |
|---|---|
| 0 | 土台。スキーマ確定、シード、釣況リストAPIとReactが繋がるまで ✅ |
| 1 | 投稿。登録・ログイン、釣行投稿、写真 ✅ |
| 2 | 掲示板化。スレッド・返信、ルールタブ、通報 ✅（通報はAPIのみ） |
| 3 | 見やすさを詰める。サマリー最適化、フィルタのURL反映、PWA化 |
| 4 | 公開して回す。まず1つの釣り場に絞る |
